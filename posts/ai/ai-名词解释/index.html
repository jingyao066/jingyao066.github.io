RAG#

RAG（Retrieval-Augmented Generation，检索增强生成）​ 是一种将 信息检索​ 与 大语言模型（LLM）生成​ 结合的技术，用来让 AI 回答问题时能基于你提供的私有/最新知识库，而不仅依赖模型训练时的旧知识。

🔍 核心思想#

普通 LLM 只靠"大脑里记的东西"回答问题 → 容易过时、幻觉。

RAG 的做法：

  1. 检索（Retrieval）：用户提问 → 从外部知识库（文档、手册、数据库等）中查最相关的内容

  2. 增强（Augmented）：把检索到的内容作为上下文（Context）拼接到 Prompt 中

  3. 生成（Generation）：LLM 基于【检索到的资料 + 问题】生成答案

简单来说：先查资料，再让模型根据资料回答

✅ RAG 的优点#

  • 📚 可用私有数据（公司文档、客服知识库、论文等）

  • 🆕 知识可更新（只需更新知识库，不用重训模型）

  • 🧠 减少幻觉（要求模型"根据给定资料回答"）

  • 💰 成本低（比微调大模型便宜很多）

⚠️ 局限与注意#

  • 检索质量影响最终效果（垃圾进→垃圾出）

  • 需做好文档切分、向量化（Embedding）、重排（Rerank）

  • 对需要复杂多跳推理或强逻辑推理的问题仍有挑战

📌 常见应用场景#

  • 企业知识库 / 内部 Wiki 问答

  • 客服机器人（基于产品手册）

  • 法律/医疗文档问答

  • 代码库 / API 文档问答

MCP#

**MCP（Model Context Protocol，模型上下文协议）**​ 是由 Anthropic 于 2024 年底提出的开放标准协议，用于解决 AI 大模型与外部数据源/工具之间的连接问题，可简单理解为 “AI 应用的 USB 接口”——让 AI 模型能统一、安全地访问本地文件、数据库、API、业务系统等外部资源。

🔑 核心概念#

  • Host（宿主应用）：如 Claude Desktop、VS Code + Copilot、你的 AI 产品 → 运行 MCP Client

  • MCP Client：负责与 MCP Server 通信，嵌在 Host 里

  • MCP Server：轻量服务，暴露三类能力：

    • 📖 Resources（资源）：读取文件、数据库记录等（如 file://、db://）

    • 🛠️ Tools（工具）：执行操作，如调 API、运行脚本、查搜索引擎

    • 💬 Prompts（提示模板）：预定义的任务提示供 AI 调用

  • Transport（传输层）：通常基于 stdio（本地）或 HTTP+SSE（远程）

✅ 主要优势#

对比项 传统 Function Calling/插件 MCP
对接方式 每个工具单独适配 统一协议，写一次到处用
本地资源 难访问 原生支持（文件/进程）
安全控制 散乱 用户显式授权，Server 隔离
生态 封闭 开源、社区共享 MCP Server

📌 典型使用场景#

  • AI 读取你本地代码仓库并解释/重构

  • AI 查询公司内部 Wiki / Notion / 数据库

  • AI 调用 Jira、GitHub、Slack 等 SaaS API 创建 Issue 或发消息

  • 浏览器中的 AI 助理通过 MCP 操控页面/标签页

🛠️ 简单类比#

就像 USB 标准​ 让不同外设（鼠标、U盘、键盘）插到任何电脑都能用——

MCP 让任意 AI 模型统一接入任意外部工具/数据，无需为每个组合单独开发集成。
