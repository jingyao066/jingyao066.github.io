Spring DevTools集成指南#

什么是Spring DevTools？#

Spring DevTools是Spring Boot提供的开发工具集，主要功能：

  • 快速重启 (Fast Restart): 修改代码后自动快速重启，只需 5-10秒
  • 自动重新加载 (Live Reload): 浏览器自动刷新
  • 配置属性验证: 开发时验证配置属性

为什么需要DevTools？#

当前问题#

  • 项目完整启动需要 10分钟
  • 即使优化后也需要 3-5分钟
  • 每次修改代码都需要完全重启
  • 严重影响开发效率

使用DevTools后#

  • 首次启动: 3-5分钟 (优化后)
  • 后续修改代码: 只需 5-10秒 热重启
  • 开发效率提升 95%+

### 步骤3: 配置IDEA  
  
#### 3.1 启用自动编译  
1. 打开 Settings (Mac: `⌘+,`, Windows: `Ctrl+Alt+S`)  
2. 导航到: `Build, Execution, Deployment` -> `Compiler`  
3. ✅ 勾选 `Build project automatically`  
4. ✅ 勾选 `Compile independent modules in parallel`  
  
#### 3.2 允许运行时自动构建  
1. 打开 Settings  
2. 导航到: `Advanced Settings`  
3. 找到 `Compiler` 部分  
4. ✅ 勾选 `Allow auto-make to start even if developed application is currently running`  
  
#### 3.3 配置文件监控排除  
1. Settings -> Build, Execution, Deployment -> Compiler  
2. 在 `Excludes` 中添加不需要监控的目录:  
   - `build/**`  
   - `target/**`  
   - `.gradle/**`

## 工作原理  
  
### 双类加载器机制  
  
DevTools使用两个类加载器：  
  
1. **Base ClassLoader**:   
- 加载不会改变的类 (依赖库、第三方jar)  
- 不会重新加载  
  
2. **Restart ClassLoader**:   
- 加载项目代码  
- 修改后重新加载  
  
这样重启时只需要重新加载项目代码，不需要重新加载所有依赖，因此速度很快。  
  
---  
  
## 触发重启的条件  
  
### 自动触发  
- 修改 `.java` 文件  
- 修改 `.properties` 文件  
- 修改 `.yml` 文件  
- 修改 `resources` 目录下的文件  
  
### 手动触发  
如果自动触发不工作，可以手动触发：  
- Mac: `⌘+F9` (Build Project)  
- Windows: `Ctrl+F9` (Build Project)  
  
### 不会触发的情况  
- 修改静态资源文件 (如果配置了排除)  
- 修改 `build/` 目录下的文件  
- 修改配置中排除的目录

## 配置选项详解  
  
### restart配置  
  
```yaml  
spring:  
devtools:    restart:      enabled: true              # 启用/禁用重启功能  
   additional-paths:          # 额外监控的路径  
     - src/main/java      exclude:                   # 排除不触发重启的路径  
     - static/**        - public/**      quiet-period: 400          # 安静期(ms) - 等待变化稳定  
   poll-interval: 1000        # 轮询间隔(ms)  
   log-condition-evaluation-delta: false  # 不输出条件评估日志

常见问题#

Q1: DevTools不工作，没有自动重启？#

检查项:

  1. ✅ IDEA是否启用了自动编译？
    • Settings -> Compiler -> Build project automatically
  2. ✅ IDEA是否允许运行时自动构建？
    • Settings -> Advanced Settings -> Allow auto-make…
  3. ✅ 是否正确添加了依赖？
    • 检查 build.gradle
  4. ✅ 是否保存了文件？
    • 按 ⌘+S / Ctrl+S

Q2: 重启太频繁，影响开发？#

解决方案:

1
2
3

spring:  
  devtools:    restart:      quiet-period: 2000  # 增加安静期到2秒  
      poll-interval: 3000 # 增加轮询间隔到3秒

Q3: 某些类修改后不生效？#

原因:

  • 可能是静态变量或单例模式的类
  • Spring容器缓存的对象

解决方案:

  • 完全重启应用 (Stop -> Start)
  • 避免在开发时使用过多静态变量

Q4: DevTools会影响生产环境吗？#

不会:

  • 使用 developmentOnly 依赖
  • 生产环境打包时会自动排除
  • 即使不小心打包，DevTools也会自动禁用

Q5: 修改配置文件后不生效？#

原因:

  • 某些配置需要完全重启
  • Apollo远程配置不会通过DevTools重新加载

解决方案:

  • 重要配置修改后完全重启
  • 或使用Apollo动态刷新功能

## 最佳实践  
  
### 1. 分层启动  
- **首次启动**: 使用优化配置 (3-5分钟)  
- **后续开发**: 依赖DevTools快速重启 (5-10秒)  
  
### 2. 合理配置排除路径  
- 排除不需要的静态资源  
- 排除配置文件 (如果不常修改)  
- 减少不必要的重启  
  
### 3. 团队协作  
- 确保所有开发者都配置了DevTools  
- 统一配置文件 (application-fast.yml)  
- 分享最佳实践  
  
### 4. 与其他工具配合  
- IDEA热部署  
- JRebel (商业工具，效果更好但收费)  
- Docker开发环境
